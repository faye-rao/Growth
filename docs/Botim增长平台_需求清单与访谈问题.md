## 第二部分 · 见 Radhika / Growth team 关键问题清单

> 用途：这是把主文档里所有 🟡 项转成的访谈提纲。**🔴 必问**=直接决定方案可行性/范围/优先级，没答案就无法往下；**⚪ 建议问**=完善设计、锦上添花。
> GZF 建议直接赴迪拜**完整跟跑一次活动**（系统怎么用即清楚），由裴青/腾鑫安排——很多问题在跟跑中会自然有答案。

### A. 战略与优先级（先锁 Phase 1 北极星）
- 🔴 **A1** Phase 1 上线的**北极星指标**到底是哪一个？目标量级多少？（DAU/MAU、Fintech 激活率、跨产品转化率、ARPU？）GZF 只给了"不低于现状"的底线。
- 🔴 **A2** 渗透率口径确认：通话用户→Fintech **当月渗透率**当前多少、今年目标多少？（⚠️ 原表 15% / 录音 10%，必须钉死一个数）
- 🔴 **A3** 6 条产品线（VoIP / Remittance / Merchant / Card / Wallet / Lending）中 **Phase 1 主推哪一个**、为什么？（GZF：战略落点 Loan、当前流量最大 Remittance）
- ⚪ **A4** 若只聚焦一个用户群——激活沉默 / 留存现有 Fintech / cross-sell——哪个 ROI 最可控？第二个产品的目标用户特征是什么？

### B. Cohort 与分群（决定 P0-1 复刻范围）
- 🔴 **B1** 最常用的 **3~5 个 Cohort** 是哪些？各自如何定义（底层规则/SQL）？当前规模多少？（数据专项 D13）
- 🔴 **B2** 规则引擎支持几层嵌套？有哪些**时间窗算子**（过去 N 天 / 最近 1 次 / 累计…）？（D15）
- 🔴 **B3** 配过但**过去 90 天从未触发**的 Cohort/Segment 有多少？（用于界定真实替换范围，避免复刻僵尸规则）
- ⚪ **B4** 分群结果多久刷新一次（实时 / T+1 / 周）？跑一次大分群（>1000 万）要多久？（D14）
- ⚪ **B5** 你对哪些用户群的画像最熟？（冷启动期一线"用户直觉"常比模型准）

### C. 活动与编排（决定 P1-3 / P2-2 模板设计）
- 🔴 **C1** 2026 至今实际跑了多少活动？各类型（Push/SMS/In-App）占比？共覆盖多少种 Cohort 定义？（GZF：系统上约 800 个）
- 🔴 **C2** 现在**每月都在跑**的活动模板有哪几个？（我方先实现 3~5 个）
- ⚪ **C3** 一个活动从立项到上线要多久？瓶颈在哪步（提需求 / 等数据 / 写文案 / 审批）？
- ⚪ **C4** 过去 3 个月效果**最好**与**最差**各 1~2 个活动是哪个？原因是 offer / 文案 / 时机？（D18 复盘报告）
- ⚪ **C5** Flow 在用的节点类型有几种（延时 / 分支 / A·B / 等待事件 / webhook）？最复杂的那条长什么样、能截图吗？

### D. 触达与渠道（决定 P0-2 / P1-7）
- 🔴 **D1** 现有 **In-App 活动位**有几个、分别在哪些页面？哪些位置可扩展为活动位？（需配合前端 PM）
- 🔴 **D2** 各渠道**每用户频次上限**应该定多少？（结合 UAE 政策与用户疲劳度——当前系统无上限）
- ⚪ **D3** 现有渠道的**发送失败率 / 到达率**具体数字？Android vs iOS 差多少？有无兜底渠道？
- ⚪ **D4** 是否仍有"**测试人群专属通道**"？（Shadow 实验要用，避免影响正式流量）

### E. 效果验证与复盘（决定 P1-5 / P1-6 口径）
- 🔴 **E1** 运营**真正在看的 5~10 张报表/漏斗**是哪些？谁看、多久看一次？（限过去 90 天有访问的；新系统须复现且数字对得上）
- 🔴 **E2** "活动成功"的口径是全公司统一（CTR/CVR/ROI）还是每活动自定？归因窗口多长、谁定的？（D19、D21）
- ⚪ **E3** 复盘最常分析哪几个维度？能否提供最近 3 个月分析报告 + 对应数据/SQL？
- ⚪ **E4** MoEngage 内部计算的指标（RFM / churn score / engagement）有没有人在用？停用后谁受影响？（D26，排隐藏依赖）

### F. 实时性（⚠️ 直接决定 2 个月能否替换）
- 🔴 **F1** **实时活动 vs 批量活动各占多少比例**？（实时 > 30% 则 2 个月内很难替换；全 T+1 则难度骤降——这是最关键的可行性判断）
- 🔴 **F2** 触发型活动（如"开户后 10 分钟推一条"）现在怎么实现？依赖谁的实时事件流？
- ⚪ **F3** 实时事件流（Kafka 类）当前可用性如何？Shadow 期间能否订阅？（D31）

### G. Shadow 验证落地（W5–W6 交付）
- 🔴 **G1** 选**哪个高频场景**做"一周内能看到结果"的快速验证？（如钱包激活 Push）
- 🔴 **G2** 对照组怎么选——"留 5% 不动"还是随机分流？用现有规则引擎切流量是否可行？
- ⚪ **G3** Shadow 期间能否实时拿到 MoEngage 侧触达流水？接入方式与延迟？新旧系统如何**去重**避免双发？（D23、D24）
- ⚪ **G4** Shadow 观测周期预计几天？结果报告应长什么样？

### H. 现场跟跑（最高价值，建议优先安排）
- 🔴 **H1** 能否完整 **shadowing 一次**某运营"产生想法 → 提需求 → 拿数据 → 配置活动 → 上线"全过程？（≤4 小时，裴青/腾鑫安排）—— 上面一半问题会在此自然解答。
