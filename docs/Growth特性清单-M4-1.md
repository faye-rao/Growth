## 0. 模块定位
- **优先级**：P0（"我方做的 3 个核心功能"之一——③Campaign 漏斗追踪，Survey 结论#6 / row76）。
- **基线**：复刻 MoEngage 每次推送的埋点漏斗——"查看 → 点击 → 转化"，口径基本统一（点击率/转化率，row15）；并**吸收原 Reports 独立大模块**（重新分析 line24 "收敛进 Campaign 漏斗追踪 + Shadow 对照报告"）。

## 5. 前置阻塞与风险
- **R1 口径未全公司统一**（D29）→ 转化/活跃/留存无统一定义，**开发前先与 Growth/数据组对齐口径**，否则 A5/B 归因返工（重新分析 line185）。
- **R2 跨产品漏斗强依赖跨业务线 ID 打通**（M8/E2）→ 无 email 前提，ID-mapping 覆盖率/准确率决定 C1–C4 是否可算（row31 / 重新分析 line84）。
- **R3 真看报表清单未知**（row14）→ 无统一清单（GZF：因产品形态不同各人关注点不同→Growth），D13/D25 未拿到则 D1/D2 报表范围与 A2 漏斗清单无法精准（重新分析 line176）。
- **R4 触达日志/事件 schema 未到位**（M8/裴青/数据组）→ 不到位则 A1 埋点与 F1 算料无法动工。

## 6. Phase 落地建议
- **Phase 1（W3–W6）**：先打通**单活动"查看→点击→转化"漏斗（A1–A3）+ 1–2 天归因（B1）**，供 M7 Shadow 对照报告（D2，Shadow ready）使用；与 MoEngage 双跑对账(D3)建立"数字对得上"。这是 Phase 1 验收命门的一环（重新分析 line128 W5–W6 Shadow）。
- **Phase 2+**：**跨产品漏斗(C)在跨业务线 ID 打通后**作为差异化亮点重点投入；补节点级流失可视(A4)、可配归因窗口(B2)、自动归因洞察(D4，🤖AI 增量)、NL2SQL/轻看板呈现(E) 横向铺开。
- **建议顺序**：先关 R1 口径 + R3 报表清单 + R4 日志/schema 前置 → MVP 跑通一个高频场景（如钱包激活 Push）的单活动漏斗 + 对账 → ID 打通后投入跨产品漏斗差异化。
