## 0. 模块定位
- **优先级**：P2（可后置；与数据组协作）。属"明确降配"模块——非我方 3 个核心功能（Survey 结论#6）。
- **基线（克制）**：**不做全量 BI**，只复现 MoEngage 上"**真有人看**"的 **5–10 张报表/漏斗**且**数字对得上**（row14）。
- **刻意降配的理由（重要事实）**：
  - **Dashboard/看板由数据组马老板单独重建**，Botim 本身有底层数据 → **我方无需做这块**（row14/74）。
  - **产品侧另用 Amplitude 做 BI**（与 MoEngage 埋点重复，"**花了两份钱**"）；**Botim 无 CDP**、业务线数据未打通（row75/26/52）。
  - 故 M9 = **只搬真有人看的报表 + 数据分析自动化**，并**主动与数据组/Amplitude 划界避免重复**。
- **增量主线**：克制范围 + **🤖AI 数据分析自动化**（活动后自动复盘洞察/异常归因，Plan W3–W4），兑现"增量靠 AI"（row6）。
- **现状事实**：报表无统一清单、各产品线关注点不同（row14）；活动成功口径基本统一（查看→点击→转化，row15）；跨产品漏斗已并入 M4，不在此重复；MoEngage 内部计算指标（RFM/predicted churn/engagement score）是否有人在用尚待 Growth 确认（row57）。

## 2. 🤖 AI 与 ★增强 特性汇总（相对 MoEngage 的差异化）

## 5. 前置阻塞与风险
- **R1 报表清单未知** → row14 明确**无统一清单**（各产品线关注点不同）→ 不拿到 D25 真看报表清单则 A1–A4 做哪些无法精准（Growth）。
- **R2 与数据组/Amplitude 范围重复** → Dashboard 归数据组（row74）、产品侧已有 Amplitude（row75，"花了两份钱"）→ **必须先划界**，否则重复建设（A5）。
- **R3 内部衍生指标若有人用、停用受影响** → MoEngage 内部 RFM/churn/engagement（row57/D26）若有消费方，**停用前须在 M2/M8 补齐**，否则下游断（C1）。
- **R4 现有 BI 工具栈未知** → D27 未拿到则与数据组协作边界与复用范围不清，影响 A5 划界与 D1 接入。

## 6. Phase 落地建议
- **优先级 P2，可后置**（合同一年期、倾向不续约，其余可慢换，row77）。
- **Phase 1（W3–W4 最小集）**：仅"**搬 5–10 张真有人看报表 + 自动化分析**"最小集（Plan W3-W4），**与数据组协作、不与 Amplitude 重复**。
- **Phase 2+**：补全 B2 异常归因、B3 NL2SQL 自助问数；完成 C1 内部指标排查并联动 M2/M8 补齐（若需）。
- **建议顺序**：① 先关 D25/D26/D27 与 row57 前置访谈 → ② 与数据组划清看板/数据源边界（A5）→ ③ 搬真看报表最小集并校验"数字对得上"（A1）→ ④ 叠加自动化分析（B1）。
