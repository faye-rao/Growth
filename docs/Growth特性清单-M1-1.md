> 类型图例：**【复刻】** 对标 MoEngage、替换必备 ｜ **【★增强】** 本次新增/优于 MoEngage ｜ **【🤖AI】** AI 能力（增量主线）。

## 0. 模块定位
- **优先级**：**P0 最高**（Survey 结论#3/#7：替换优先级最高 = 触达 Push/notification + In-App 弹窗，其次用户分群，row73）。
- **基线**：复刻 MoEngage 触达执行——Push/SMS 走 Botim 自有通道、In-App 弹窗 SDK 自渲染，补全触达日志（重新分析 M1 节）。
- **增量主线**：在"不低于现状"基线上，叠加**送达可达性预测/无效用户过滤**、**多渠道兜底**、**统一灵活活动位框架**、**统一频控接入点**等体验增强，正面解决 Survey 点名的"选到已卸载用户永远收不到、Android 到达率低于 iOS"（row43）。
- **现状事实**：
  - Push/SMS 由 **Botim 自发**，MoEngage 仅做编排/调接口，Botim 已收口、MoEngage **无直接推送权限**；**无 Email**（row40/53）。
  - In-App 弹窗 = MoEngage **SDK 直接渲染、不过 Botim 后端**（row40）。
  - **无固定活动位**，按页面灵活配置（弹窗、评分等都算活动）（row41）。
  - 限速：曾设人工审核，现改为**接口侧限速**，防系统/被推页面被打爆（row22/47）。
  - Opt-out：MoEngage 维护名单、可导出；发送时取名单后调 Botim API（row48）。
  - **Botim 侧无跨活动去重、无每用户每日上限**，仅推送限速；一天可能收到多条（row38/42）。
  - 量级：活动有大有小，**最大约百万级/活动**（row54）。

## 2. 🤖 AI 与 ★增强 特性汇总（相对 MoEngage 的差异化）

**🤖 AI 能力（增量主线，对齐 row6 "增量靠 AI"）**
- M1-F2 送达可达性预测与排序 ← **触达侧最强亮点，直击"选到已卸载/低活跃永远收不到、Android<iOS"**（row43）

**★ 本次增强（优于 MoEngage 现状）**
- M1-F1 无效用户过滤（已卸载/长期离线/低活跃，提升有效送达，row43）
- M1-A5 多渠道兜底降级（Push 失败 → SMS/In-App，破"无兜底渠道"，row43）
- M1-B4 统一灵活活动位框架（"页面×位置"中台 + 位置-效果数据，破"无固定活动位"，row41）
- M1-C2 统一频控接入点（触达执行侧统一接入，Push 现无频控，row37/38）

**一句话定位**：M1 = **复刻 MoEngage 触达执行（Push/SMS 自发通道 A1–A4 + In-App SDK 自渲染 B1–B3 + 限速 C1 + Opt-out D + 触达日志 E）+ 触达侧增强（送达可达性 F + 多渠道兜底 A5 + 活动位框架 B4 + 频控接入 C2）**，是 P0 最高优先级，触达日志（E）前置 M4/M7。

## 5. 前置阻塞与风险
- **R1 到达率不可控** → 依赖三方（Google/APNS）+ 用户是否在线；**Android 到达率低于 iOS**；范围很大且与所选用户活跃度强相关，**选到已卸载用户则永远收不到**（row43）。→ 以 F1 无效用户过滤 + F2 可达性预测 + A5 多渠道兜底缓解。
- **R2 Shadow 测试专属通道现状待确认** → Botim 之前有"测试人群专属通道"，现是否仍有需 Growth 确认（row44）；缺失则影响 M7 Shadow 不污染正式流量。
- **R3 无 Email 渠道缺失** → MoEngage/Botim 现状均无 Email（row40/53），跨渠道兜底链路只能在 Push/SMS/In-App 之间组织。
- **R4 限速/Opt-out 接口为外部依赖** → 限速与 Opt-out 主体在 Botim 开放平台（row47/48），接口规格未明则 C1/D1 难精准估算。
- **R5 无系统级频控/去重** → Botim 侧无跨活动去重、无每用户每日上限（row38/42），跨活动频控主体在 M3，M1 仅做执行侧接入（C2），需与 M3 边界对齐避免返工。

## 6. Phase 落地建议
- **Phase 1（优先级最高）**：先打通 **Push + In-App** 一个高频场景（如**钱包激活 Push**）的发送 + 触达日志埋点（A1/B1 + C1 + D1 + E1），供 **M4 漏斗 / M7 Shadow** 直接消费。
- **Phase 2+**：补全多渠道兜底(A5)、统一活动位框架(B4)、统一频控接入点(C2)、送达可达性预测/无效用户过滤(F1/F2) 横向铺开。
- **建议顺序**：先关 Growth/开放平台前置（活动位清单、到达率数字、限速/Opt-out 接口、测试专属通道现状）→ MVP 跑通钱包激活 Push 的发送 + 触达日志 → 验证后扩可达性 AI 增量。
