## 0. 模块定位
- **优先级**：**P0 前置**（M8 是 M2 圈人 / M4 漏斗 / M9 行为分析 / M7 Shadow 的**底座**，无 M8 则下游无法动工，重新分析 §5.1）。
- **基线定位**：**不是重建数仓**。**T+1 清洗主体由数据组马老板做，我方是消费方 + 补齐触达日志**——本模块只做"**接入 + 消费 + 补缺 + 服务化**"四件事（重新分析 line86）。
- **两个数据来源**：①footprint（Botim 自有埋点平台）直接取 ②数据组清洗后提供（row28）。
- **现状事实**：footprint 留**全量备份**（接入时即预判 MoEngage 会被替换），但目前**几乎无人查看**（row49）；事件 schema 有文档，但建议从 footprint 经数据组拉取（比文档更准更全，row50）；Botim **无 CDP**、仅数据库（row52）；**无 email**、业务线 ID 是否统一/有无 Mapping 待查（row31）；**无回写、无下游消费**（row55/56）；触达/转化日志完整记录到用户级（row63）。
- **核心增量逻辑**：把"几乎无人看"的 footprint 全量备份**激活**为自研数据底座的金矿，**无需重新埋点**（row49）。

## 2. 🤖 AI 与 ★增强 特性汇总（相对现状的差异化）

**★ 本次增强（优于现状）**
- **M8-A4 激活沉睡的 footprint 全量备份 ← 最强亮点**：这份"几乎无人看"的全量备份正是自研底座的现成金矿，**无需重新埋点**（row49）。
- M8-A5 Kafka 事件流订阅（近实时通道）：为准实时抑制供数（row59/61/D31）。
- M8-B2 跨业务线 ID 打通（无 email）：customer_id/手机号主键 + Mapping 消费，支撑跨产品漏斗/cross-sell（row31/D2）。
- M8-C3 触达日志主体由我方补齐（补缺非搬运，row55/56/63）。
- M8-E3 轻量 DQC（D32）。
- **M8-F1 "已转化不再推"准实时抑制**：survey 指实时诉求**主要就为此** → 轻量实时层即可，不必全链路实时（row59）。
- **M8-F3 替换无中断风险**：无回写无下游（row55/56）→ 利好快速低风险替换。

> 注：M8 为底座层，**无 🤖AI 主线特性**（AI 增量集中在 M2 NL2SQL / M6 文案 / M9 自动化分析）；M8 通过宽表/服务化为上游 AI 供数。

**一句话定位**：M8 = **接入 footprint 全量备份(A) + 消费数据组 ID-Mapping 与标签(B/D3) + 补齐触达/转化日志(C) + 圈人/漏斗宽表(D) + 轻 DQC(E) + 准实时抑制与服务化(F)**；不重建数仓，做"接入+消费+补缺+服务化"，把沉睡备份激活为下游底座。

## 5. 前置阻塞与风险
- **R1 数据样本 + 事件 schema 未到位** → M2/M4 无法动工（裴青/数据组，row50/51）。**这是开 Phase 1 前的第一硬阻塞。**
- **R2 ID-Mapping 覆盖率/准确率未知** → 无 email 前提下，D2 Mapping 覆盖率/准确率决定 B2 跨业务线打通难度与 cross-sell 可达性（数据组 D2）。
- **R3 MoEngage 内部衍生指标是否有人在用需排查** → MoEngage 内部计算的 **RFM / predicted churn / engagement score** 是否有人在用待查（row57）；**若有人用，停用前需在 M8/M2 补齐，否则受影响**。
- **R4 实时事件流可用性是准实时抑制的开关** → D31 事件流可用性决定 F1 "已转化不再推"准实时抑制可行性（若实时流不稳，F1 降配为更短批次）。

## 6. Phase 落地建议
- **M8 是最前置模块**。**Phase 1 W1–W2（摸清家底）即需拿到：数据样本 + 事件 schema + ID-mapping 现状**（重新分析 §4.1）。
- **Phase 1（W3–W4）落地顺序**：先打通"**接 footprint(A1/A4) + 消费数据组标签(D3) + 触达日志宽表(C1)**"供 M2/M4 用；圈人/漏斗宽表(D1/D2)随 M2/M4 MVP 同步。
- **Phase 2+**：补全 Kafka 实时通道(A5)、准实时抑制层(F1)、轻 DQC(E1–E3) 横向铺开；据 R3 排查结果决定是否在 M8/M2 补衍生指标。
- **完整替换 P-A 阶段**（重新分析 §4.2）：M8 + M1 先落地（3–4 周），底座与触达执行优先。
